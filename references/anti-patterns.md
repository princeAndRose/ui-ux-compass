# Contextual failure patterns

These are diagnostic hypotheses. Establish an observed user impact before recommending a change.

| Pattern | When it becomes a problem | Valid alternative context |
| --- | --- | --- |
| Equal-weight cards | Different priorities become indistinguishable | Peer collections or deliberate comparisons |
| Dense layout | Grouping, targets, or scanning prevent the task | Expert operational tools with readable rows |
| Sparse layout | Necessary context is hidden or comparison becomes tedious | Focused service steps or immersive storytelling |
| Gradients, glass, shadows | Text loses legibility or depth implies false affordances | Deliberate brand expression or supported platform materials |
| Multiple CTAs | Labels/priority obscure the next action | Peer actions in an editor or exploration surface |
| Modal interaction | Repeated interruption loses context or blocks recovery | A focused, bounded decision with usable dismissal |
| Decorative imagery | Distracts from or misrepresents the content | Editorial storytelling, expressive identity, useful explanation |
| Missing states | Required failure/loading/empty paths leave the user stuck | Static local content where these states do not apply |

Never ban a font, effect, color, or layout merely because it is common. The user's chosen system and task determine whether the pattern works.
